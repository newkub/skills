# อัปเดต README Files

## เมื่อใดควรใช้
ใช้ workflow นี้เมื่อคุณต้องการ:
- อัปเดต README.md files ทั่วทุก workspaces
- ทำให้ documentation formats และ structures เป็นมาตรฐาน
- ให้แน่ใจว่า project descriptions สม่ำเสมอ
- รักษาคำแนะนำการติดตั้งและการใช้งานที่ถูกต้อง
- อัปเดต project metadata และ badges

## Quick Start
1. อ่าน README files ปัจจุบันใน workspaces ทั้งหมด
2. ใช้โครงสร้าง README template มาตรฐาน
3. อัปเดต project descriptions และ features
4. ตรวจสอบว่า installation instructions ทำงานถูกต้อง
5. ทดสอบ documentation links และ references ทั้งหมด

## Steps

### 1. อ่าน README Files ปัจจุบัน
ตรวจสอบ README.md files ที่มีอยู่ใน directories ทั้งหมด
ระบุ formatting inconsistencies และข้อมูลที่ล้าสมัย
บันทึก README patterns และ sections ที่หายไป

**Verification:** ยืนยันว่า README files ทั้งหมดถูกบันทึกรายการและวิเคราะห์

### 2. ใช้โครงสร้างมาตรฐาน
อัปเดต README files ทั้งหมดให้ทำตาม template ที่สม่ำเสมอ
ให้แน่ใจว่า section ordering และ headings ถูกต้อง
ใช้ standard markdown formatting rules
รวม sections ที่จำเป็น: description, installation, usage

**Verification:** ตรวจสอบว่า structure ตรงกับ README standards สำหรับแต่ละ workspace type

### 3. อัปเดตข้อมูลโปรเจกต์
เขียน project descriptions ที่ชัดเจนโดยใช้ active voice
อัปเดต feature lists พร้อม capabilities ปัจจุบัน
ให้แน่ใจว่าความถูกต้องทางเทคนิคใน descriptions ทั้งหมด
เพิ่ม badges และ status indicators ที่เหมาะสม

**Verification:** ยืนยันว่าข้อมูลโปรเจกต์ทั้งหมดถูกต้องและเป็นปัจจุบัน

### 4. ตรวจสอบ Installation Instructions
ทดสอบ installation commands และ procedures ทั้งหมด
อัปเดต dependency versions และ requirements
ให้แน่ใจว่า setup instructions ทำงานสำหรับผู้ใช้ใหม่
เพิ่ม troubleshooting guidance สำหรับปัญหาทั่วไป

**Verification:** ยืนยันว่า installation procedures ทำงานถูกต้อง

### 5. อัปเดต Documentation Links
ตรวจสอบว่า internal links ทั้งหมดชี้ไปยังไฟล์ที่ถูกต้อง
อัปเดต external references และ resources
ตรวจสอบ workflow links และ skill references
ให้แน่ใจว่า cross-references ทั้งหมดใช้งานได้

**Verification:** ทดสอบว่า links และ references ทั้งหมดทำงานได้อย่างเหมาะสม

## Expected Outcomes
- README files ทั้งหมดใช้ formatting ที่สม่ำเสมอ
- Project descriptions ชัดเจนและถูกต้อง
- Installation instructions ทำงานถูกต้อง
- Documentation links ใช้งานได้และเป็นปัจจุบัน
- README files ให้ภาพรวมโปรเจกต์อย่างครบถ้วน

## Error Handling
- ถ้า installation commands ล้มเหลว อัปเดตด้วย alternatives ที่ทำงานได้
- ถ้า links เสีย หา replacement resources หรือลบ broken references
- ถ้า formatting conflicts เกิดขึ้น ให้ความสำคัญกับ workspace-specific standards
- ถ้า project descriptions ไม่ชัดเจน เขียนใหม่ด้วย active voice

## Best Practices
- รักษา README files ให้กระชับแต่ครบถ้วน
- ใช้ headings ที่ชัดเจนและ formatting ที่สม่ำเสมอ
- ทดสอบ instructions ก่อนเผยแพร่
- อัปเดต README files เมื่อโปรเจกต์ features เปลี่ยน
- รวม examples และ usage patterns เพื่อความชัดเจน
