# อัปเดต Global Workflows

## เมื่อใดควรใช้
ใช้ workflow นี้เมื่อคุณต้องการ:
- อัปเดต global workflow files ทั่วทุก skills
- ทำให้ workflow formats และ structures เป็นมาตรฐาน
- ใช้ workflow guidelines ใหม่อย่างสม่ำเสมอ
- รักษาคุณภาพและความสอดคล้องของ workflow
- ซิงโครไนซ์การเปลี่ยนแปลง workflow ข้ามโปรเจกต์

## Quick Start
1. อ่าน global workflow files ปัจจุบัน
2. ใช้ writing guidelines และ standards ใหม่
3. อัปเดต workflow structures และ formats
4. ตรวจสอบความสอดคล้องกับ best practices
5. ทดสอบ workflows ที่อัปเดตทั้งหมด

## Steps

### 1. อ่าน Global Workflows ปัจจุบัน
ตรวจสอบ workflow files ที่มีอยู่ใน skill directories ทั้งหมด
ระบุ formatting inconsistencies และโครงสร้างที่ล้าสมัย
บันทึก workflow patterns และปัญหาปัจจุบัน

**Verification:** ยืนยันว่า workflow files ทั้งหมดถูกบันทึกรายการ

### 2. ใช้ Writing Guidelines
อัปเดต workflows ทั้งหมดให้ทำตาม active voice rules
ให้แน่ใจว่าประโยคสั้นกว่า 20 คำ
ใช้ standard markdown formatting อย่างสม่ำเสมอ
ลบ passive voice และภาษาที่ไม่ชัดเจน

**Verification:** ตรวจสอบว่าประโยคทั้งหมดเป็นไปตามข้อกำหนดความยาวและ voice

### 3. อัปเดต Workflow Structures
ทำให้ section ordering เป็นมาตรฐานใน workflows ทั้งหมด
ให้แน่ใจว่า frontmatter formatting ถูกต้อง
ใช้ consistent naming conventions
ตรวจสอบว่า workflow references ถูกต้อง

**Verification:** ยืนยันว่า structures ตรงกับ write-workflows standards

### 4. ตรวจสอบ Best Practices Compliance
ตรวจสอบว่า workflow length ไม่เกิน 300 บรรทัด
ให้แน่ใจว่า step count อยู่ภายใต้ 15 steps
ตรวจสอบว่า workflows เป็น self-contained
ลบ magic numbers และ hardcoded values

**Verification:** ยืนยันว่า workflows ทั้งหมดสอดคล้องกับ best practices

### 5. ทดสอบ Workflows ที่อัปเดต
รัน sample workflows เพื่อตรวจสอบ functionality
ตรวจสอบว่า links และ references ทำงานถูกต้อง
ทดสอบ workflow integration กับ tools
ตรวจสอบ error handling และ verification steps

**Verification:** ให้แน่ใจว่า workflows ทั้งหมดรันโดยไม่มี errors

## Expected Outcomes
- Global workflows ทั้งหมดใช้ formatting ที่สม่ำเสมอ
- Writing guidelines ถูกใช้อย่างสม่ำเสมอ
- Best practices compliance ถูกบรรลุ
- Workflows เป็น self-contained และ functional
- คุณภาพ documentation ดีขึ้นอย่างมีนัยสำคัญ

## Error Handling
- ถ้า workflows เกินขีดจำกัดความยาว  refactor เป็น components ที่เล็กกว่า
- ถ้า references เสีย อัปเดต workflows ที่เชื่อมโยงทั้งหมด
- ถ้า formatting conflicts เกิดขึ้น ให้ความสำคัญกับ write-workflows standards
- ถ้าการทดสอบล้มเหลว ตรวจสอบและแก้ไข sections ที่ได้รับผลกระทบ

## Best Practices
- อัปเดต workflows ตามลำดับ dependency ที่เป็นเหตุเป็นผล
- ทดสอบ workflow แต่ละอันก่อน batch updates
- เก็บ backup copies ก่อนการเปลี่ยนแปลงครั้งใหญ่
- บันทึก structural modifications ทั้งหมด
- ใช้ version control เพื่อติดตามการเปลี่ยนแปลงอย่างเป็นระบบ
