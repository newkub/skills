# JSPM 4.0.0 Release

**Release Date:** 2024

## Overview

JSPM 4.0 represents a significant update with a refreshed, opinionated standards-based workflow.

## What's New

### Standards-Based Workflow

JSPM 4.0 leans into web standards with convention over configuration:

- Native ES Modules without transpilation
- Import Maps as package management artifacts
- TypeScript type stripping (not compilation)
- No custom loaders

### Import Map as Lockfile

Import maps now treated as lockfiles, not manifests:

```javascript
// importmap.js - generated and managed by JSPM
((map) => {
  document.head.appendChild(Object.assign(
    document.createElement("script"),
    { type: "importmap", innerHTML: JSON.stringify(map) }
  ));
})({
  imports: { /* managed by JSPM */ },
  scopes: { /* managed by JSPM */ }
});
```

### package.json as Manifest

User manifest moved to package.json:

```json
{
  "name": "my-app",
  "exports": { ".": "./src/index.ts" },
  "dependencies": { "lit": "^3.0.0" }
}
```

### Development Server

New jspm serve with instant HMR:

- Zero configuration
- Fast refresh
- TypeScript type stripping
- SSE-based hot reloading

### Production Build

jspm build with production semantics:

```bash
jspm build
```

## Breaking Changes

### No More Manual importmap.json Editing

importmap.js is now auto-generated - do not edit manually.

### Entry Points Required

Must define exports in package.json for entry points.

## Migration from 3.x

1. Run jspm install to regenerate importmap.js
2. Ensure package.json has exports field
3. Update import map references in HTML

## Benefits

- Simplified debugging (no source maps needed)
- Portable code (fewer framework conventions)
- Future-proof (standards compliant)
- Reduced tooling (less configuration)
- Instant development (browser-ready imports)
