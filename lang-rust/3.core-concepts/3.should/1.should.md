# Rust Best Practices

## Code Style

### Naming Conventions

- Use snake_case for variables and functions
- Use PascalCase for types and traits
- Use SCREAMING_SNAKE_CASE for constants
- Name types descriptively

### Code Organization

- Keep functions small and focused
- Limit function complexity
- Group related functionality
- Use modules for organization

## Error Handling

### Result Types

- Prefer Result over Option for errors
- Use ? operator for propagation
- Create custom error types
- Handle all error cases

### Panic Usage

- Only panic for unrecoverable errors
- Avoid panics in library code
- Use expect() with clear messages
- Document panic conditions

## Performance

### Memory Management

- Prefer stack allocation
- Avoid unnecessary allocations
- Use references over copies
- Profile before optimizing

### Algorithm Choice

- Choose appropriate data structures
- Consider algorithmic complexity
- Use iterators effectively
- Leverage standard library

## Testing

### Test Coverage

- Write unit tests for functions
- Add integration tests for features
- Test error conditions
- Use property-based testing

### Test Quality

- Make tests fast and independent
- Use descriptive test names
- Test public APIs only
- Maintain test documentation

## Documentation

### Code Comments

- Document public APIs
- Explain complex algorithms
- Provide usage examples
- Keep comments current

### API Design

- Design clear interfaces
- Provide ergonomic APIs
- Document invariants
- Include examples in docs

## Verification

Run clippy regularly. Format code with rustfmt. Maintain high test coverage. Review code for best practices.
