# Error Handling in Rust

## Overview

Rust handles errors through Result<T, E> and Option<T>. It enables explicit error handling without exceptions. Errors must be handled at compile time.

## Key Concepts

### Result<T, E> Type

- Ok(T) represents success values
- Err(E) represents error values
- Forces error handling at compile time
- No exceptions, only recoverable errors

### Option<T> Type

- Some(T) represents present values
- None represents absent values
- Handles nullable values safely
- Prevents null pointer dereferences

### Error Propagation

- Use ? operator for error propagation
- Use From trait for error conversion
- Create custom error types with Error trait
- Chain errors with source() method

### Panic vs Result

- Use panic for unrecoverable errors
- Use Result for recoverable errors
- Use panic!() macro for explicit panics
- Use catch_unwind for panic recovery

## Examples

### Basic Result Usage

```rust
use std::fs::File;
use std::io::{self, Read};

fn read_file_content(path: &str) -> Result<String, io::Error> {
    let mut file = File::open(path)?;
    let mut content = String::new();
    file.read_to_string(&mut content)?;
    Ok(content)
}

fn main() {
    match read_file_content("test.txt") {
        Ok(content) => println!("File content: {}", content),
        Err(error) => println!("Error reading file: {}", error),
    }
}
```

### Option Handling

```rust
fn find_dividend(numbers: &[i32], divisor: i32) -> Option<i32> {
    numbers.iter().find(|&&n| n % divisor == 0).copied()
}

fn main() {
    let numbers = vec![1, 2, 3, 4, 5, 6];

    match find_dividend(&numbers, 3) {
        Some(result) => println!("Found number divisible by 3: {}", result),
        None => println!("No number divisible by 3 found"),
    }
}
```

### Custom Error Type

```rust
use std::fmt;

#[derive(Debug)]
enum AppError {
    InvalidInput(String),
    NetworkError,
    DatabaseError(String),
}

impl fmt::Display for AppError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            AppError::InvalidInput(msg) => write!(f, "Invalid input: {}", msg),
            AppError::NetworkError => write!(f, "Network error occurred"),
            AppError::DatabaseError(msg) => write!(f, "Database error: {}", msg),
        }
    }
}

impl std::error::Error for AppError {}

fn process_data(input: &str) -> Result<String, AppError> {
    if input.is_empty() {
        return Err(AppError::InvalidInput("Input cannot be empty".to_string()));
    }

    Ok(format!("Processed: {}", input))
}
```

### Error Propagation with ?

```rust
use std::fs;
use std::io::{self, Write};

fn save_processed_data(data: &str, filename: &str) -> Result<(), io::Error> {
    let processed = format!("PROCESSED: {}", data);
    fs::write(filename, processed)?;
    Ok(())
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let data = "example data";
    save_processed_data(data, "output.txt")?;
    println!("Data saved successfully");
    Ok(())
}
```

## Best Practices

1. Use Result for recoverable errors
2. Use Option for nullable values
3. Implement Error trait for custom errors
4. Use ? operator for propagation
5. Provide context with errors
6. Document error conditions

## Error Handling Patterns

### Early Returns

```rust
fn validate_user_input(input: &str) -> Result<String, String> {
    if input.is_empty() {
        return Err("Input cannot be empty".to_string());
    }

    if input.len() > 100 {
        return Err("Input too long".to_string());
    }

    Ok(input.to_string())
}
```

### Error Mapping

```rust
use std::num::ParseIntError;

fn parse_number(s: &str) -> Result<i32, String> {
    s.parse::<i32>()
        .map_err(|e| format!("Failed to parse '{}': {}", s, e))
}
```
