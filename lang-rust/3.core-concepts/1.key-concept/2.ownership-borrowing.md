# Ownership and Borrowing

## Overview

Rust's ownership system is its most unique feature. It enables memory safety without garbage collection through compile-time checks of ownership, borrowing, and lifetimes.

## Key Concepts

### Ownership Rules

1. Each value has an owner
2. Only one owner at a time
3. Owner is dropped when scope ends

### Move Semantics

- Assignment moves ownership by default
- Copy trait for types that can be copied
- Clone trait for explicit deep copying

### Borrowing Rules

- Any number of immutable borrows allowed
- Only one mutable borrow allowed
- Cannot have mutable and immutable borrows simultaneously

### Lifetimes

- Ensure references don't outlive their data
- Explicit lifetime annotations when needed
- Lifetime elision rules for common cases

## Examples

### Move vs Copy

```rust
fn main() {
    let x = 5; // i32 implements Copy
    let y = x; // x is copied to y
    println!("x = {}, y = {}", x, y); // Both valid

    let s1 = String::from("hello"); // String doesn't implement Copy
    let s2 = s1; // s1 is moved to s2
    // println!("{}", s1); // Error: s1 is no longer valid
    println!("{}", s2); // OK
}
```

### Borrowing

```rust
fn main() {
    let mut s = String::from("hello");

    // Immutable borrowing
    let r1 = &s;
    let r2 = &s;
    println!("r1: {}, r2: {}", r1, r2);

    // Mutable borrowing
    let r3 = &mut s;
    r3.push_str(", world");
    println!("r3: {}", r3);
}
```

### Lifetime Annotations

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}

fn main() {
    let string1 = String::from("abcd");
    let string2 = "xyz";

    let result = longest(&string1, string2);
    println!("The longest string is {}", result);
}
```

## Best Practices

1. **Prefer borrowing over cloning** - Avoid unnecessary allocations
2. **Use references for function parameters** - Pass by reference when not taking ownership
3. **Keep lifetimes short** - Minimize scope of borrows
4. **Use Cow for conditional ownership** - Clone-on-write for flexible ownership
5. **Leverage lifetime elision** - Let compiler infer lifetimes when possible

## Common Pitfalls

1. **Dangling references** - References to dropped data
2. **Multiple mutable borrows** - Violating borrowing rules
3. **Lifetime complexity** - Over-annotating lifetimes
4. **Unnecessary clones** - Performance overhead
