# Rust Core Concepts

## Overview

Rust ensures memory safety without garbage collection. It provides performance comparable to C/C++. The ownership system guarantees safety.

## Key Concepts

### Ownership System
- Each value has one owner
- Only one owner exists at a time
- Owner drops when scope ends
- Prevents memory leaks and dangling pointers

### Borrowing
- References borrow values without ownership
- Multiple immutable borrows allowed
- Only one mutable borrow at a time
- Prevents data races at compile time

### Lifetimes
- Use explicit lifetime annotations
- Compiler verifies reference validity
- Prevents use-after-free errors
- Lifetime elision reduces verbosity

### Type System
- Strong static typing
- Type inference reduces verbosity
- Generic types enable code reuse
- Trait system provides polymorphism

### Pattern Matching
- Destructure with match expressions
- Exhaustive checking handles all cases
- Guards add conditions
- Provides concise control flow

## Examples

### Basic Ownership
```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1; // s1 moves to s2
    // println!("{}", s1); // Error: s1 invalid
    println!("{}", s2); // OK
}
```

### Borrowing
```rust
fn main() {
    let s1 = String::from("hello");
    let len = calculate_length(&s1); // Borrow s1
    println!("Length of '{}' is {}.", s1, len); // s1 valid
}

fn calculate_length(s: &String) -> usize {
    s.len()
} // s drops but no ownership lost
```

### Pattern Matching
```rust
fn main() {
    let number = 13;
    
    match number {
        1 => println!("One"),
        2 | 3 | 5 | 7 | 11 => println!("Prime"),
        13..=19 => println!("Teen"),
        _ => println!("Other"),
    }
}
```

## Best Practices

1. Use ownership semantics for data transfer
2. Prefer borrowing over cloning
3. Leverage type system for domain modeling
4. Use pattern matching over if-else chains
5. Follow naming conventions strictly
