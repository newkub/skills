## Prerequisites

- เข้าใจว่ากำลังรับคำขออะไรและจากใคร
- มีช่องทางการสื่อสารที่ชัดเจนกับผู้ขอ
- พร้อมที่จะรับข้อมูลและ context ที่จำเป็น

## 3.1 Precondition

- ได้รับคำขอหรือคำสั่งที่ชัดเจน
- มีข้อมูลผู้ขอ (requester) และวัตถุประสงค์หลัก
- เข้าใจ priority และ urgency ของงาน
- มี access พื้นฐานสำหรับเริ่มต้นการทำงาน

## 3.2 Prepare

- เตรียมรับข้อมูลทั้งหมดที่เกี่ยวข้อง
- ตรวจสอบว่ามี resources และ tools พร้อมใช้งาน
- ทำความเข้าใจขอบเขตงานเบื้องต้น
- เตรียมสร้าง context สำหรับการทำงาน

## 3.3 Execute

1. รับและบันทึกคำขออย่างเป็นระบบ

   - อ่านคำขอให้ครบถ้วนและเข้าใจทุกรายละเอียด โดยใช้ `read_file` หรือ context ที่มี
   - บันทึก requirements หลักและรอง โดยใช้ `create_memory` หากจำเป็นจัดเก็บระยะยาว
   - ระบุ success criteria ที่คาดหวัง โดยใช้ `ask_user_question` เมื่อต้องการ clarification
   - สร้าง task ID หรือ reference สำหรับติดตาม

2. ถามเพื่อทำความเข้าใจที่ชัดเจน

   - ถามคำถามเพื่อเติมเต็ม missing information โดยใช้ `ask_user_question`
   - ยืนยันความเข้าใจโดยสรุปกลับไปให้ผู้ใช้ตรวจสอบ
   - ขอ clarification สำหรับจุดที่คลุมเครือหรือกว้างเกินไป
   - ระบุ assumptions ที่ต้องยืนยันและใช้ `ask_user_question` เมื่อมีหลายทางเลือก

3. จัดระเบียบข้อมูลที่ได้รับ

   - จัดหมวดหมู่ข้อมูลตามประเภท (technical, business, design, etc.)
   - ระบุ dependencies ที่อาจมีผลต่องานโดยใช้ `search_web` หรือ `skill` ดู best practices
   - สร้าง task context สำหรับการทำงานต่อ โดยบันทึกสรุปที่ชัดเจน
   - บันทึก constraints และ limitations ที่ต้องระวัง

## 3.4 Validate

- [ ] คำขอถูกบันทึกครบถ้วนและถูกต้อง
- [ ] ความเข้าใจตรงกับความต้องการของผู้ขอ
- [ ] ข้อมูลที่จำเป็นถูกรวบรวมครบแล้ว
- [ ] Assumptions ที่สำคัญได้รับการยืนยัน
- [ ] พร้อมที่จะเข้าสู่ phase การวิเคราะห์

## 3.5 Verify

- [ ] ยืนยันว่าไม่มีความเข้าใจผิดใน requirements
- [ ] ตรวจสอบความสมบูรณ์ของข้อมูลที่ได้รับ
- [ ] ยืนยันว่าพร้อมดำเนินการต่อได้
- [ ] ตรวจสอบว่า context ที่สร้างมีประโยชน์ต่อทีมงาน
- [ ] ยืนยันว่า task อยู่ใน scope ที่สามารถทำได้
