## Prerequisites

- Requirements และ architecture ชัดเจน
- เข้าใจ team capabilities
- มี budget และ resource constraints

## 3.1 Precondition

- Functional และ non-functional requirements กำหนดแล้ว
- Architecture approach ถูกเลือกแล้ว
- Constraints (budget, time, skills) รู้จัก
- Decision makers พร้อม

## 3.2 Prepare

- ระบุ technology categories ที่ต้องเลือก
- กำหนด evaluation criteria
- รวบรวม candidate technologies
- เตรียม comparison templates

## 3.3 Execute

1. Research options

   - ใช้ `search_web` หา technology comparisons
   - ใช้ `skill` โหลด tech-specific knowledge
   - ใช้ `mcp2_resolve-library-id` หา library info
   - ใช้ `mcp1_search_cloudflare_documentation` หา platform docs

2. Evaluate alternatives

   - ใช้ `ask_user_question` collect team input
   - สร้าง comparison matrices
   - ประเมิน pros/cons แต่ละ option
   - ใช้ `todo_list` track evaluation

3. Make selections

   - ใช้ `write_to_file` document decisions
   - ใช้ `create_memory` บันทึก rationale
   - ใช้ `edit` update tech stack docs
   - สร้าง migration หรือ adoption plan

## 3.4 Validate

- [ ] Technologies ตรงตาม requirements
- [ ] Team มี skills หรือ can learn
- [ ] Costs อยู่ใน budget
- [ ] Integration เป็นไปได้

## 3.5 Verify

- [ ] ยืนยันว่า selections approved
- [ ] ตรวจสอบว่า PoC สำเร็จ (ถ้ามี)
- [ ] ยืนยันว่าพร้อมเริ่ม development
- [ ] ตรวจสอบว่า documented
