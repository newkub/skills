# Boy Scout Rule vs Scheduled Refactoring

## เปรียบเทียบ

| หัวข้อ | Boy Scout Rule | Scheduled Refactoring |
|--------|----------------|----------------------|
| **Timing** | With every change | Dedicated time |
| **Scope** | Touch only changed code | Broader system |
| **Cost** | Small, distributed | Large, concentrated |
| **Consistency** | Gradual improvement | Periodic leaps |
| **Planning** | Opportunistic | Scheduled sprints |
| **Visibility** | Invisible | Visible project |
| **Backlog** | No separate items | Dedicated backlog |
| **Team Buy-in** | Cultural norm | Requires allocation |
| **Risk** | Lower per change | Higher concentrated |
| **Best For** | Mature teams, maintenance | Major modernization |

## เมื่อไหร่ใช้อะไร

- **Boy Scout Rule**: Continuous improvement, maintenance mode, team habit
- **Scheduled Refactoring**: Legacy modernization, tech stack changes
