# Build Terms Glossary

## A
**AST** - Abstract Syntax Tree โครงสร้างแผนภูมิของโค้ด

**Asset** - ไฟล์ที่ไม่ใช่โค้ด (images, fonts, CSS)

**Async** - Asynchronous operations ที่ไม่บล็อก execution

**Automation** - การทำงานอัตโนมัติ

## B
**Bundle** - ไฟล์ที่รวมโค้ดหลายๆ ไฟล์เข้าด้วยกัน

**Bundler** - เครื่องมือสร้าง bundles

**Build** - กระบวนการแปลง source code เป็น production-ready code

**Build Cache** - การเก็บผลลัพธ์จาก builds ก่อนหน้า

## C
**Cache** - การจัดเก็บข้อมูลชั่วคราวเพื่อเรียกใช้ซ้ำ

**CI/CD** - Continuous Integration/Continuous Deployment

**Clean Build** - build จาก source โดยไม่ใช้ cache

**Code Splitting** - การแบ่งโค้ดเป็น chunks

**Compiler** - เครื่องมือแปลงโค้ดจากภาษาหนึ่งไปอีกภาษาหนึ่ง

**Compression** - การลดขนาดไฟล์

## D
**Dependency** - libraries/packages ที่โปรเจกต์ต้องการ

**Dependency Graph** - โครงสร้างความสัมพันธ์ของ dependencies

**Dev Server** - server สำหรับ development พร้อม hot reload

**Dynamic Import** - การ import modules ตอน runtime

## E
**Entry Point** - จุดเริ่มต้นของ application

**Environment Variables** - ตัวแปรสภาพแวดล้อม

**ESM** - ES Modules ระบบ modules มาตรฐานของ JavaScript

**Executor** - ตัวทำงานใน build systems

## F
**File System** - ระบบจัดการไฟล์

**Framework** - โครงสร้างพื้นฐานสำหรับ development

**Frontend** - ส่วนของ user interface

**Full Stack** - ทั้ง frontend และ backend

## H
**Hash** - ค่าที่สร้างจาก content สำหรับ caching

**Hot Module Replacement** - การอัพเดท modules โดยไม่ต้อง reload

**Hydration** - การเชื่อมต่อ server-rendered HTML กับ JavaScript

## I
**Incremental Build** - build เฉพาะส่วนที่เปลี่ยนแปลง

**Integration** - การเชื่อมต่อระบบต่างๆ

**Interpreter** - ตัวดำเนินการโค้ดทันที

**IO** - Input/Output operations

## J
**JavaScript** - ภาษาโปรแกรมสำหรับ web

**JSON** - JavaScript Object Notation รูปแบบข้อมูล

**JIT** - Just-In-Time compilation

**JSX** - JavaScript XML syntax extension

## L
**Lazy Loading** - การโหลด resources เฉพาะตอนที่จำเป็น

**Library** - collection ของ reusable code

**Linker** - เครื่องมือเชื่อมโยง object files

**Loader** - เครื่องมือแปลงไฟล์ใน build process

## M
**Manifest** - ไฟล์รายการ assets และ dependencies

**Minification** - การลดขนาดโค้ดโดยลบช่องว่างและ comments

**Module** - หน่วยของโค้ดที่สามารถนำกลับมาใช้ซ้ำ

**Monorepo** - repository เดียวที่มีหลายโปรเจกต์

## N
**Node.js** - JavaScript runtime สำหรับ server-side

**NPM** - Node Package Manager

**Namespace** - การจัดกลุ่ม identifiers

**Native** - โค้ดที่ทำงานโดยตรงบน platform

## O
**Optimization** - การปรับปรุงประสิทธิภาพ

**Output** - ผลลัพธ์จาก build process

**Overhead** - ทรัพยากรเพิ่มเติมที่จำเป็น

**Object File** - ไฟล์ที่ compile แล้วแต่ยังไม่ link

## P
**Package** - หน่วยของ distributable code

**Pipeline** - ลำดับของ processing steps

**Plugin** - component ที่ขยายฟังก์ชันระบบ

**Polyfill** - โค้ดที่เพิ่ม features สำหรับ browsers เก่า

## R
**Rebuild** - การ build ใหม่หลังจากมีการเปลี่ยนแปลง

**Refactor** - การปรับปรุงโครงสร้างโค้ด

**Registry** - ที่เก็บ packages

**Resolver** - ตัวหาพาธของ modules

## S
**Source Map** - ไฟล์ map โค้ดที่ compile กลับไปหา source

**Static Analysis** - การวิเคราะห์โค้ดโดยไม่รัน

**Symlink** - Symbolic link ไปยังไฟล์/โฟลเดอร์อื่น

**Sync** - Synchronous operations ที่บล็อก execution

## T
**Task** - หน่วยของงานใน build process

**Tree Shaking** - การลบโค้ดที่ไม่ได้ใช้

**Transpiler** - เครื่องมือแปลง syntax ของภาษาเดิมๆ

**TypeScript** - JavaScript พร้อม type system

## V
**Version** - รุ่นของ software

**Vendor** - third-party libraries

**Virtual** - ที่จำลองขึ้นมา

**Vite** - Modern build tool

## W
**Watch Mode** - โหมดที่ monitor การเปลี่ยนแปลงไฟล์

**Webpack** - Popular module bundler

**Worker** - Thread สำหรับ background tasks

**Workspace** - พื้นที่ทำงานของโปรเจกต์
