# Design Docs vs ADRs

## เปรียบเทียบ

| หัวข้อ | Design Documents | ADRs (Architecture Decision Records) |
|--------|------------------|-------------------------------------|
| **Scope** | Complete system design | Single decision context |
| **Lifecycle** | Project phase | Persistent record |
| **Audience** | Implementers, stakeholders | Future maintainers |
| **Format** | Flexible, comprehensive | Standard template |
| **Timing** | Before implementation | At decision point |
| **Updates** | Living document | Superseded by new ADR |
| **Location** | Wiki, docs folder | Git repo, alongside code |
| **Searchability** | Hard to find context | Version controlled |
| **Maintenance** | Often outdated | Explicit status |
| **Best For** | Greenfield projects | Ongoing, evolutionary architecture |

## เมื่อไหร่ใช้อะไร

- **Design Docs**: New projects, comprehensive planning, onboarding
- **ADRs**: Continuous development, decision archaeology, maintenance
