# Code Comments vs Self-Documenting Code

## เปรียบเทียบ

| หัวข้อ | Code Comments | Self-Documenting Code |
|--------|---------------|---------------------|
| **Approach** | Explain with words | Expressive naming, structure |
| **Maintenance** | Drift risk (lies) | Always current |
| **Reading Speed** | Jump between file/comment | Linear flow |
| **Complexity** | Can hide bad code | Forces simplicity |
| **Intent** | Why documented | What is clear |
| **Onboarding** | Helpful context | Faster pattern recognition |
| **APIs** | JSDoc required | Types + naming |
| **Overhead** | Writing + updating | Just naming |
| **Review Focus** | Comment accuracy | Code clarity |
| **Ideal** | Minimal, "why" only | Descriptive, intention-revealing |

## เมื่อไหร่ใช้อะไร

- **Comments**: Business logic, complex algorithms, external references
- **Self-Documenting**: Clean code, domain models, standard patterns
