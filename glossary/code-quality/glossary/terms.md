# Code Quality Terms Glossary

## A
**Accessibility** - การทำให้ผู้พิการสามารถใช้งานได้

**Agile** - Methodology สำหรับ development แบบ iterative

**Anti-pattern** - รูปแบบการเขียนโค้ดที่ไม่ดี

**API** - Application Programming Interface

**Architecture** - โครงสร้างระดับสูงของระบบ

**Assertion** - การตรวจสอบความถูกต้องในโค้ด

## B
**Backward Compatibility** - ความสามารถทำงานกับเวอร์ชันเก่า

**Benchmark** - การทดสอบประสิทธิภาพ

**Best Practice** - วิธีการที่ดีที่สุดที่ยอมรับกัน

**Bug** - ข้อผิดพลาดในโค้ด

**Build** - กระบวนการ compile และ package โค้ด

## C
**CI/CD** - Continuous Integration/Continuous Deployment

**Clean Code** - โค้ดที่อ่านง่ายและดูแลง่าย

**Code Review** - การตรวจสอบโค้ดโดยผู้อื่น

**Code Smell** - การบ่งชี้ว่าโค้ดอาจมีปัญหา

**Cohesion** - ความสัมพันธ์ระหว่าง elements ใน module เดียวกัน

**Complexity** - ความซับซ้อนของโค้ด

**Coupling** - ความสัมพันธ์ระหว่าง modules ต่างๆ

**Coverage** - สัดส่วนของโค้ดที่ถูกทดสอบ

**CRUD** - Create, Read, Update, Delete operations

## D
**Debugging** - การหาและแก้ไขข้อผิดพลาด

**Decoupling** - การลดการพึ่งพาระหว่าง components

**Dependency** - การพึ่งพาภายนอก

**Design Pattern** - รูปแบบการออกแบบที่ใช้ซ้ำได้

**Documentation** - เอกสารประกอบโค้ด

**DRY** - Don't Repeat Yourself principle

## E
**Edge Case** - สถานการณ์พิเศษที่เกิดขึ้นน้อย

**Encapsulation** - การซ่อน implementation details

**End-to-End Test** - การทดสอบทั้งระบบ

**Enterprise** - ระดับองค์กรขนาดใหญ่

**Error Handling** - การจัดการข้อผิดพลาด

**Exception** - เหตุการณ์ผิดปกติที่ interrupt flow

## F
**Factory** - Pattern สำหรับสร้าง objects

**Feature** - ฟังก์ชันการทำงานของระบบ

**Framework** - โครงสร้างพื้นฐานสำหรับ development

**Frontend** - ส่วนของ user interface

**Function** - หน่วยของโค้ดที่ทำงานเฉพาะทาง

## G
**Git** - Version control system

**GitHub** - Platform สำหรับ Git repositories

**Global Variable** - ตัวแปรที่เข้าถึงได้ทุกที่

**Grep** - Tool สำหรับค้นหาข้อความ

## H
**Hardcoding** - การใส่ค่าคงที่โดยตรงในโค้ด

**Hook** - จุดที่สามารถแทรก logic ได้

**Hotfix** - การแก้ไขปัญหาเร่งด่วน

**HTML** - HyperText Markup Language

## I
**IDE** - Integrated Development Environment

**Immutable** - ข้อมูลที่ไม่สามารถเปลี่ยนแปลงได้

**Implementation** - การนำ design มาเป็นโค้ดจริง

**Inheritance** - การสืบทอดคุณสมบัติใน OOP

**Integration** - การเชื่อมต่อระบบต่างๆ

**Interface** - สัญญาระหว่าง components

**Iteration** - รอบของ development

## J
**JavaScript** - ภาษาโปรแกรมสำหรับ web

**JSON** - JavaScript Object Notation

**JSDoc** - Documentation standard สำหรับ JavaScript

**Jest** - JavaScript testing framework

**JIRA** - Project management tool

## K
**KISS** - Keep It Simple, Stupid principle

**Keyword** - คำสงวนในภาษาโปรแกรม

**Kit** - Set ของ tools หรือ libraries

## L
**Lambda** - Anonymous function

**Legacy Code** - โค้ดเก่าที่ยังใช้งานอยู่

**Library** - Collection ของ reusable code

**Linting** - การตรวจสอบคุณภาพโค้ดอัตโนมัติ

**Logging** - การบันทึกข้อมูลการทำงาน

**Loop** - การทำงานซ้ำ

## M
**Maintainability** - ความง่ายในการดูแลรักษาโค้ด

**Magic Number** - ตัวเลขที่ไม่มีความหมายชัดเจน

**Method** - function ใน class

**Microservice** - Service ขนาดเล็กที่ทำงานอิสระ

**Migration** - การย้ายข้อมูลหรือโค้ด

**Mock** - object จำลองสำหรับ testing

**Module** - หน่วยของโค้ดที่สามารถนำกลับมาใช้ซ้ำ

## N
**Namespace** - การจัดกลุ่ม identifiers

**Node.js** - JavaScript runtime สำหรับ server-side

**NPM** - Node Package Manager

**Null** - ค่าว่างในการเขียนโปรแกรม

## O
**Object** - หน่วยข้อมูลที่มี properties และ methods

**OOP** - Object-Oriented Programming

**Open Source** - ซอฟต์แวร์ที่เปิดเผย source code

**Optimization** - การปรับปรุงประสิทธิภาพ

**Overengineering** - การทำให้ซับซ้อนเกินความจำเป็น

## P
**Package** - หน่วยของ distributable code

**Pattern** - รูปแบบที่ใช้ซ้ำได้

**Performance** - ประสิทธิภาพของระบบ

**Pipeline** - ลำดับของ processing steps

**Plugin** - component ที่ขยายฟังก์ชันระบบ

**Polymorphism** - การมีหลายรูปแบบใน OOP

**Production** - สภาพแวดล้อมจริง

**Prototype** - ต้นแบบของระบบ

## Q
**Quality** - คุณภาพของซอฟต์แวร์

**Query** - การสอบถามข้อมูล

**Queue** - โครงสร้างข้อมูลแบบ FIFO

## R
**Refactoring** - การปรับปรุงโครงสร้างโค้ด

**Regression** - ปัญหาที่กลับมาหลังจากแก้ไข

**Release** - การเผยแพร่เวอร์ชันใหม่

**Repository** - ที่เก็บ source code

**Requirements** - ความต้องการของระบบ

**Reusable** - สามารถนำกลับมาใช้ซ้ำได้

**Review** - การตรวจสอบ

**Runtime** - ช่วงเวลาที่โปรแกรมทำงาน

## S
**Scalability** - ความสามารถในการขยายระบบ

**Scope** - ขอบเขตของตัวแปรหรือฟังก์ชัน

**Security** - ความปลอดภัยของระบบ

**Service** - หน่วยงานที่ให้บริการ

**Singleton** - Pattern ที่มี instance เดียว

**Solid** - หลักการ 5 ข้อสำหรับ OOP

**Source Code** - โค้ดต้นฉบับ

**Static** - ที่เกิดขึ้นตอน compile time

**Story** - user story ใน agile development

**Style Guide** - แนวทางการเขียนโค้ด

**Syntax** - กฎการเขียนภาษา

## T
**Technical Debt** - ค่าใช้จ่ายจากการเลือก solutions ที่ไม่ดีในระยะยาว

**Template** - แม่แบบสำหรับสร้างโค้ด

**Test** - การทดสอบโค้ด

**Thread** - หน่วยของ execution

**Throw** - การสร้าง exception

**Tool** - เครื่องมือสำหรับ development

**Type** - ชนิดของข้อมูล

**TypeScript** - JavaScript พร้อม type system

## U
**UI** - User Interface

**UX** - User Experience

**Unit Test** - การทดสอบแต่ละส่วน

**Update** - การอัพเดท

**Usability** - ความง่ายในการใช้งาน

**Use Case** - สถานการณ์การใช้งาน

**Utility** - ฟังก์ชันทั่วไปที่ใช้ซ้ำได้

## V
**Validation** - การตรวจสอบความถูกต้อง

**Variable** - ตัวแปร

**Version** - รุ่นของซอฟต์แวร์

**View** - ส่วนแสดงผลใน MVC pattern

**Vulnerability** - จุดอ่อนด้านความปลอดภัย

## W
**Warning** - คำเตือนจาก linting หรือ compiler

**Waterfall** - Model การพัฒนาแบบตามลำดับ

**Webhook** - callback ผ่าน HTTP

**Workflow** - ลำดับการทำงาน

**Wrapper** - class ที่ห่อหุ้ม functionality อื่น

## Y
**YAGNI** - You Aren't Gonna Need It principle

**Yarn** - Package manager สำหรับ JavaScript

**YAML** - รูปแบบข้อมูลแบบ human-readable

## Z
**Zero-day** - vulnerability ที่ยังไม่เคยถูกเปิดเผย

**Zone** - พื้นที่ execution ในบาง frameworks

**Zoom** - การขยาย/ย่อใน UI
