# Full-Stack vs Frontend-Backend Split

## เปรียบเทียบ

| หัวข้อ | Full-Stack Developers | Frontend/Backend Split |
|--------|----------------------|------------------------|
| **Scope** | End-to-end ownership | Specialized deep expertise |
| **Context Switching** | Database to UI | Domain deep dive |
| **Team Size** | Smaller teams | Larger teams |
| **Bottlenecks** | Fewer handoffs | API contract coordination |
| **Expertise** | Breadth over depth | Depth over breadth |
| **Hiring** | Harder to find | Easier, specialized |
| **Ownership** | Feature-based | Layer-based |
| **Learning** | Constant context switch | Deep specialization |
| **Autonomy** | Ship complete features | Dependent on others |
| **Best For** | Startups, small teams | Scale, complex domains |

## เมื่อไหร่ใช้อะไร

- **Full-Stack**: Startups, rapid iteration, feature squads
- **Split**: Large orgs, performance critical, security boundaries
