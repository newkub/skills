# Simplicity Principles

## Why Simplicity Matters

Simplicity ทำให้เอกสาร:
- เข้าใจง่ายขึ้น
- maintain ง่ายขึ้น
- อ่านได้เร็วขึ้น
- ลด cognitive load

## Keep It Simple

### Minimal Content

- เขียน content ที่จำเป็นเท่านั้น
- หลีกเลี่ยง redundancy
- ลบ content ที่ไม่จำเป็น
- focus บน essentials

### Simple Language

- ใช้ words ที่ simple
- หลีกเลี่ยง complex sentences
- ใช้ active voice
- หลีกเลี่ยง jargon

### Simple Structure

- ใช้ hierarchy ที่ flat
- หลีกเลี่ยง deep nesting
- ใช้ sections ที่ชัดเจน
- หลีกเลี่ยง complex organization

## Avoid Over-Engineering

### Don't Over-Format

- ใช้ formatting ที่จำเป็นเท่านั้น
- หลีกเลี่ยง excessive emphasis
- หลีกเลี่ยง decorative elements
- focus บน readability

### Don't Over-Structure

- หลีกเลี่ยง excessive sections
- หลีกเลี่ยง excessive subsections
- ใช้ structure ที่ minimal
- focus บน organization

### Don't Over-Document

- หลีกเลี่ยง documenting obvious things
- focus บน non-obvious
- ให้ context ที่จำเป็น
- หลีกเลี่ยง verbosity

## Progressive Disclosure

### Start Simple

- เริ่มด้วย basics
- เพิ่ม complexity ตามลำดับ
- ให้ optional details
- allow skipping

### Layer Information

- ใช้ sections สำหรับ different levels
- ใช้ expandable sections
- ใช้ links สำหรับ details
- allow exploration

### Hide Complexity

- ซ่อน advanced topics
- ให้ optional reading
- ใช้ appendices
- ใช้ footnotes

## Focus on Essentials

### Core Concepts

- focus บน core concepts
- อธิบาย fundamentals
- ให้ mental models
- หลีกเลี่ยง edge cases

### Key Information

- highlight key information
- ใช้ emphasis อย่างประหยัด
- ใช้ summaries
- ใช้ takeaways

### Critical Paths

- identify critical paths
- focus บน common scenarios
- ให้ happy path
- ให้ error paths

## Reduce Cognitive Load

### Short Sections

- ใช้ sections ที่สั้น
- ใช้ paragraphs ที่สั้น
- ใช้ lists สำหรับ breaking up
- ใช้ whitespace

### Visual Breaks

- ใช้ headers สำหรับ breaks
- ใช้ horizontal rules
- ใช้ images สำหรับ breaks
- ใช้ code blocks สำหรับ breaks

### Scannable Content

- ใช้ descriptive headers
- ใช้ bullet points
- ใช้ bold สำหรับ emphasis
- ใช้ tables สำหรับ summaries

## Eliminate Redundancy

### Avoid Repetition

- หลีกเลี่ยง repeating information
- ใช้ references แทน repetition
- ใช้ cross-references
- consolidate similar content

### Single Source of Truth

- ให้ information ในที่เดียว
- ใช้ references ไปยัง source
- หลีกเลี่ยง duplication
- maintain consistency

### DRY Principle

- Don't Repeat Yourself
- ใช้ includes หากจำเป็น
- ใช้ templates
- ใช้ components

## Practical Simplicity

### Use Templates

- ใช้ templates สำหรับ consistency
- ใช้ patterns สำหรับ efficiency
- ใช้ components สำหรับ reusability
- maintain standards

### Follow Conventions

- ใช้ standard formats
- ใช้ common patterns
- ใช้ established practices
- reduce learning curve

### Leverage Tools

- ใช้ linters
- ใช้ validators
- ใช้ formatters
- automate consistency
