# RFC Process vs Direct Implementation

## เปรียบเทียบ

| หัวข้อ | RFC (Request for Comments) | Direct Implementation |
|--------|---------------------------|---------------------|
| **Timing** | Before coding | Immediate start |
| **Review** | Peer feedback on design | Code review only |
| **Stakeholders** | Wide input invited | Core team only |
| **Documentation** | Design rationale | Code comments |
| **Buy-in** | Consensus building | Post-hoc acceptance |
| **Speed** | Slower start | Faster delivery |
| **Quality** | Fewer rewrites | Iterative fixes |
| **Scale** | Large changes | Small changes |
| **Visibility** | Cross-team alignment | Siloed |
| **Best For** | Architecture, APIs, significant changes | Bug fixes, minor features |

## เมื่อไหร่ใช้อะไร

- **RFC**: Architecture decisions, breaking changes, cross-team impact
- **Direct**: Hotfixes, trivial changes, urgent needs
