# Architecture Terms Glossary

## A
**API Gateway** - Entry point สำหรับ routing requests ไปยัง microservices ต่างๆ

**Async/Await** - Syntax สำหรับจัดการ asynchronous operations ใน JavaScript

**Authentication** - การตรวจสอบสิทธิ์ผู้ใช้ (who you are)

**Authorization** - การกำหนดสิทธิ์การเข้าถึง (what you can do)

## C
**Caching** - การจัดเก็บข้อมูลชั่วคราวเพื่อเพิ่ม performance

**CI/CD** - Continuous Integration/Continuous Deployment

**Client-Server** - Model ที่แบ่งระบบเป็น client และ server

**Cloud Native** - Applications ที่ออกแบบมาสำหรับ cloud environment

## D
**Database** - ระบบจัดเก็บข้อมูลแบบ structured/unstructured

**DDD** - Domain-Driven Design

**Decoupling** - การลดการพึ่งพาระหว่าง components

**Dependency Injection** - Pattern สำหรับ inject dependencies

## E
**Elasticity** - ความสามารถในการปรับขนาดตามความต้องการ

**Event-Driven** - Architecture ที่ใช้ events เป็นหลัก

**Extensibility** - ความสามารถในการขยายฟังก์ชัน

## F
**Fault Tolerance** - ความสามารถในการทำงานต่อเมื่อมี failures

**Frontend** - ส่วนของ user interface ที่ user โต้ตอบด้วย

**Full Stack** - Developer ที่ทำงานได้ทั้ง frontend และ backend

## H
**High Availability** - ระบบที่ available สูง (99.9%+ uptime)

**Horizontal Scaling** - การเพิ่ม servers แทนการเพิ่ม resources

**Hybrid Cloud** - การใช้ทั้ง public และ private clouds

## I
**Infrastructure as Code** - การจัดการ infrastructure ด้วย code

**Integration** - การเชื่อมต่อระบบต่างๆ เข้าด้วยกัน

**IoT** - Internet of Things

## L
**Load Balancer** - การกระจาย traffic ไปยัง servers หลายๆ ตัว

**Low Latency** - การตอบสนองที่รวดเร็ว

**Legacy System** - ระบบเก่าที่ยังใช้งานอยู่

## M
**Microservices** - Architecture ที่แบ่ง application เป็น services เล็กๆ

**Middleware** - Software ที่อยู่ระหว่าง OS และ applications

**Monolith** - Application เดียวที่รวมทุกฟังก์ชัน

## N
**N-Tier** - Architecture ที่แบ่งเป็นหลาย layers

**Node.js** - JavaScript runtime สำหรับ server-side

**NoSQL** - Databases ที่ไม่ใช้ SQL

## P
**Platform** - ฐานสำหรับ development/deployment

**Plugin** - Component ที่ขยายฟังก์ชันของระบบ

**Proxy** - Server ที่ทำหน้าที่เป็นตัวกลาง

## R
**Redundancy** - การมี backup systems สำหรับ reliability

**Refactoring** - การปรับปรุงโครงสร้างโค้ดโดยไม่เปลี่ยน behavior

**REST** - Representational State Transfer API style

## S
**Scalability** - ความสามารถในการรองรับ workload ที่เพิ่มขึ้น

**Serverless** - Architecture ที่ไม่ต้องจัดการ servers

**Service Mesh** - Infrastructure layer สำหรับ microservices communication

## T
**Technical Debt** - ค่าใช้จ่ายจากการเลือก solutions ที่ง่ายแต่ไม่ดีในระยะยาว

**Throttling** - การจำกัด request rate

**TypeScript** - JavaScript พร้อม types

## V
**Vertical Scaling** - การเพิ่ม resources ใน server เดียว

**Virtualization** - การสร้าง virtual versions ของ resources

**VPN** - Virtual Private Network
