# Pre-merge vs Post-merge Code Review

## เปรียบเทียบ

| หัวข้อ | Pre-merge Review | Post-merge Review |
|--------|------------------|-------------------|
| **Timing** | Before merging | After merging |
| **Blockers** | Prevents bad code | Trust-based, fix forward |
| **Speed** | Slower (approval gate) | Faster (merge then review) |
| **Context** | Fresh in mind | Historical |
| **Pressure** | Merge dependency | Can take time |
| **Quality** | Higher gate | Depends on culture |
| **Process** | Standard GitHub flow | Async, non-blocking |
| **Hotfixes** | Delayed | Immediate |
| **Learning** | Before impact | After impact |
| **Best For** | Quality-critical, junior teams | Senior teams, trunk-based |

## เมื่อไหร่ใช้อะไร

- **Pre-merge**: Quality gates, compliance, learning organizations
- **Post-merge**: High trust, continuous deployment, senior teams
