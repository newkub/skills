# Trunk-Based vs Git Flow

## เปรียบเทียบ

| หัวข้อ | Trunk-Based Development | Git Flow |
|--------|------------------------|----------|
| **Branching** | Short-lived branches | Long-lived feature branches |
| **Main Branch** | Single trunk | develop + master |
| **Merge Frequency** | Multiple times daily | At sprint/feature end |
| **Release** | Tag on trunk | Release branch |
| **Feature Flags** | Required | Not needed |
| **Complexity** | Simple | Complex branching model |
| **CI/CD** | Continuous integration | Batch integration |
| **Conflict Resolution** | Frequent, small | Rare, large |
| **Team Size** | Best for small-medium | Any size |
| **Maturity** | Modern, DevOps | Traditional, enterprise |

## เมื่อไหร่ใช้อะไร

- **Trunk-Based**: Continuous delivery, elite performers, fast feedback
- **Git Flow**: Scheduled releases, QA-heavy, regulated industries
