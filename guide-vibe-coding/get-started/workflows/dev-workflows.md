# 🧠 Dev Workflow Pipeline (ตามลำดับมาตรฐาน)

## When to Execute

ใช้เมื่อต้องการพัฒนาซอฟต์แวร์โดยทีมนักพัฒนา ที่ต้องการความคิดสร้างสรรค์ การวางแผน และการควบคุมคุณภาพ

## Quick Start

1. **Define**: กำหนดขอบเขตและเป้าหมาย
2. **Plan**: วางแผนการทำงานและประเมินเวลา
3. **Design**: ออกแบบระบบและสร้างโมเดล
4. **Implement**: เขียนโค้ดและพัฒนาฟีเจอร์
5. **Test**: ทดสอบและตรวจสอบความถูกต้อง
6. **Review**: ตรวจสอบคุณภาพโค้ด
7. **Build**: สร้างไฟล์และแพ็กเกจ
8. **Deploy**: ปล่อยระบบขึ้น Production
9. **Operate**: ดูแลระบบและเฝ้าดู
10. **Improve**: วิเคราะห์และปรับปรุงต่อเนื่อง

---

## 1️⃣ Define — กำหนดเป้าหมาย

| Action   | ความหมาย           |
| -------- | ------------------ |
| Define   | กำหนดขอบเขต        |
| Identify | ระบุปัญหา          |
| Scope    | ล็อกขอบเขตงาน      |
| Align    | ทำให้ทีมเห็นตรงกัน |

**Verification:** ตรวจสอบว่าขอบเขตชัดเจน

---

## 2️⃣ Plan — วางแผน

| Action     | ความหมาย          |
| ---------- | ----------------- |
| Plan       | วางแผน            |
| Estimate   | ประเมินเวลา       |
| Prioritize | จัดลำดับความสำคัญ |
| Roadmap    | วางแผนระยะยาว     |

**Verification:** ตรวจสอบว่าแผนสมบูรณ์

---

## 3️⃣ Design — ออกแบบ

| Action    | ความหมาย     |
| --------- | ------------ |
| Design    | ออกแบบระบบ   |
| Model     | สร้างโมเดล   |
| Architect | วางโครงสร้าง |
| Specify   | ระบุสเปก     |
| Prototype | ทำต้นแบบ     |

**Verification:** ตรวจสอบว่าดีไซน์ถูกต้อง

---

## 4️⃣ Implement — เขียนโค้ด

| Action    | ความหมาย            |
| --------- | ------------------- |
| Implement | ลงมือเขียนโค้ด       |
| Develop   | พัฒนาโค้ด           |
| Refactor  | ปรับปรุงโครงสร้างโค้ด |
| Optimize  | ปรับปรุงประสิทธิภาพ  |

**Verification:** ตรวจสอบว่าโค้ดทำงานได้

---

## 5️⃣ Test — ทดสอบ

| Action    | ความหมาย                 |
| --------- | ------------------------ |
| Test      | ทดสอบ                    |
| Validate  | ตรวจว่า “ตรงเป้าหมายไหม” |
| Verify    | ตรวจว่า “ถูกตามสเปกไหม”  |
| Simulate  | จำลองสถานการณ์           |
| Benchmark | วัดประสิทธิภาพ           |

**Verification:** ตรวจสอบว่าทุก test ผ่าน

---

## 6️⃣ Review — ตรวจคุณภาพ

| Action   | ความหมาย            |
| -------- | ------------------- |
| Review   | ตรวจโค้ด            |
| Audit    | ตรวจมาตรฐาน         |
| Approve  | อนุมัติ             |
| Gatekeep | คุมคุณภาพก่อน merge |

**Verification:** ตรวจสอบว่าผ่านการ review

---

| Action  | ความหมาย    |
| ------- | ----------- |
| Build   | สร้างไฟล์   |

| Package | แพ็กของ     |
| Version | จัดเวอร์ชัน |

**Verification:** ตรวจสอบว่า build สำเร็จ

---

## 8️⃣ Deploy — ปล่อยระบบ

| Action   | ความหมาย           |
| -------- | ------------------ |
| Deploy   | ปล่อยขึ้นระบบ      |

| Rollback | ย้อนกลับถ้ามีปัญหา |

**Verification:** ตรวจสอบว่า deploy สำเร็จ

---

## 9️⃣ Operate — ดูแลระบบ

| Action   | ความหมาย   |
| -------- | ---------- |
| Operate  | ดูแลระบบ   |

| Maintain | บำรุงรักษา |

# 📊 Dev Workflow Timeline

```
Define → Plan → Design → Implement → Test → Review → Build → Deploy → Operate → Improve
```

**Verification:** ตรวจสอบว่าลำดับถูกต้อง

## 📋 ตารางสรุป Dev Workflow

| ขั้นตอน | Action Verbs | ผลลัพธ์ที่คาดหวัง | Verification |
| -------- | ------------ | ---------------- | ------------ |
| **Define** | Identify, Scope, Align | ขอบเขตชัดเจน | ทีมเห็นตรงกัน |
| **Plan** | Estimate, Prioritize, Roadmap | แผนสมบูรณ์ | เป็นไปได้ |
| **Design** | Model, Architect, Specify | ดีไซน์ถูกต้อง | ตรงตามสเปก |
| **Implement** | Develop, Refactor, Optimize | โค้ดทำงานได้ | ผ่านการทดสอบ |
| **Test** | Validate, Verify, Simulate | ทุก test ผ่าน | ครบถ้วน |
| **Review** | Audit, Approve, Gatekeep | ผ่านการ review | มาตรฐาน |
| **Build** | Bundle, Package, Version | Build สำเร็จ | พร้อม deploy |
| **Deploy** | Release, Rollout, Rollback | Deploy สำเร็จ | ระบบทำงาน |
| **Operate** | Monitor, Log, Maintain | ระบบทำงานปกติ | เสถียร |
| **Improve** | Analyze, Iterate, Automate | ปรับปรุงมีประสิทธิภาพ | ดีขึ้น |
